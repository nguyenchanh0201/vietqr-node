# vietqr-node Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `vietqr-node`, a TypeScript port of .NET VietQR.Core + VietQR.Deeplink.Client (upstream commit `1b92450`) with full feature parity, then switch mottanrung's `vietqr-client.ts` to it.

**Architecture:** One npm package, three entry points: `vietqr-node` (payload, parse, decode, catalog, render — all offline), `vietqr-node/deeplink` (gateway client, the only network code), `vietqr-node/nestjs` (optional module). Payload output is pinned byte-for-byte to fixtures generated by running upstream .NET code. Rendering ports upstream's Skia drawing to `@napi-rs/canvas`; decoding uses `zxing-wasm` with a bundled local WASM file.

**Tech Stack:** TypeScript, Node ≥ 20, `@napi-rs/canvas`, `qrcode`, `zxing-wasm` (`/reader`), `tsup`, `vitest`. .NET 10 SDK only for the fixture generator (dev-time).

**Spec:** `docs/superpowers/specs/2026-11-04-vietqr-node-design.md` — read it before any task.

**Upstream source:** `git clone https://github.com/Ngochiendev/vietqr-core .upstream && git -C .upstream checkout 1b92450` (`.upstream/` is gitignored). "Port of X" below means: read X in `.upstream/src/VietQR.Core/` (or `VietQR.Deeplink.Client/`) and reproduce its behaviour; where upstream and the spec disagree, the spec wins.

## Global Constraints

- Package name `vietqr-node`; license MIT; LICENSE keeps `Copyright (c) 2026 Ngochiendev` alongside ours; ship ported `DISCLAIMER.md`.
- Node ≥ 20. ESM + CJS + `.d.ts` via `tsup`. Tests with `vitest`.
- No network calls anywhere except `src/deeplink/`. No runtime asset downloads or CDN fallback (incl. zxing WASM).
- Bundled assets resolve relative to the built module, never `process.cwd()`.
- `@nestjs/common` (and `@nestjs/core`, `reflect-metadata`) are optional peer deps only.
- Errors: throw `VietQrError` with stable `code`. Upstream codes and messages from `Errors/VietQrErrors.cs` are kept verbatim (`qr.missing_param`, `qr.invalid_amount`, `qr.invalid_bin`, `qr.bank_not_found`, `qr.invalid_template`, `qr.system_error`, `qr.invalid_payload`, `qr.invalid_crc`, `qr.not_vietqr`, `qr.image_decode_failed`).
- Tag 62: each sub-tag diacritics-stripped and silently truncated to 25 chars; whole tag 62 capped at 99. Payload output equals upstream byte for byte.
- Image limits (fixed constants, not options): input ≤ 10 MiB (base64 logos: bound encoded length ≤ ceil(10 MiB/3)*4 before decoding, then check decoded length); decoded ≤ 16,000,000 px and ≤ 8192 px per axis, checked from headers before raster decode; render `size` finite integer 1–4096, no clamping; every output surface ≤ 16,000,000 px.
- Templates `compact` (default) | `print` | `qr_only`; formats `png` (default) | `jpeg` | `webp` | `svg`; `centerLogoRatio` default 0.18 clamped 0.05–0.35; `size` default 500; `quality` default 100, range 1–100.
- Deeplink defaults: `defaultGateway` `https://vietqr.hiendev.io.vn`, `discoveryUrl` = upstream's value in `Configuration/VietQrDeeplinkOptions.cs`, `enableDiscovery` true, `discoveryCacheHours` 12, `timeoutSeconds` 10.
- Git (this repo): before any commit run `git config user.name "Chánh Nguyễn" && git config user.email "chanhnguyen34@gmail.com"`. No AI-attribution / `Co-Authored-By` trailers.

## Review Focus

1. **Vietnamese text in descriptions/names** (`"Thanh toán đơn hàng Đ123"`, `đ/Đ`, combining marks, emoji, `中`) — payload normalization matches upstream exactly: FormD, remove control characters and NonSpacingMark characters, map `đ/Đ` to `d/D`, then FormC. It is not an ASCII-only sanitizer: preserve surviving emoji and non-Latin characters, including upstream UTF-16 truncation/CRC behavior. Card render shows the original diacritics, not tofu boxes. Pinned by fixture cases in Task 3 and the render test `renders Vietnamese account name without missing glyphs` in Task 8.
2. **Untrusted upload bytes into `decodeImage`** — a 20 KB PNG whose header claims 60000×60000 must be rejected with `qr.image_too_large` before any pixel decode. Pinned in Task 6 (`rejects oversized dimensions from header without decoding`).
3. **Concurrent first decodes in a fresh process** — 10 parallel `decodeImage` calls must initialize the WASM once and all succeed offline. Pinned in Task 9 (`initializes zxing once under concurrency`).
4. **Unknown BIN at render time** (valid 6 digits, not in catalog) — render still succeeds with no bank logo and the BIN as the bank label, not a throw. Pinned in Task 8 (`renders unknown BIN without logo`).
5. **Payload pasted with surrounding whitespace / lowercase CRC** — `parse` trims and accepts a lowercase-hex CRC iff upstream does. Pinned by fixture cases in Task 4.
